# תכנית עבודה מפורטת — פיתוח מתמלל מקומי בסגנון Eloquent

תאריך: יוני 2026 | גרסה: 1.0

## מטרת המוצר

אפליקציית דסקטופ (תחילה Windows) לתמלול עברי מקומי לחלוטין: הקלטה חיה או קובץ → תמלול → ניקוי חכם של מילות מילוי וניסוח לפי כוונה → טקסט מוכן לשימוש בלוח, עם טרנספורמציות והיסטוריה. ללא ענן, ללא מנוי.

## עקרונות מנחים

1. **Offline-first** — שום אודיו לא עוזב את המכשיר.
2. **שני מודלים** — Whisper לתמלול, LLM לניקוי. לא מודל מולטימודלי אחד.
3. **עברית תחילה** — מודל ivrit.ai, יישור RTL בכל הממשק, טוקן שפה קבוע.
4. **בנייה מדורגת** — כל שלב מסתיים בתוצר עובד שאפשר להשתמש בו.

## שלב 0: הקמת סביבה ובדיקת היתכנות (2–3 ימים)

### משימות
- [ ] התקנת Python 3.11+, יצירת venv ייעודי
- [ ] התקנת ffmpeg (המרת פורמטים ל־16kHz mono WAV)
- [ ] התקנת faster-whisper: `pip install faster-whisper`
- [ ] הורדת המודל `ivrit-ai/whisper-large-v3-turbo-ct2` מ־HuggingFace
- [ ] התקנת Ollama והורדת מודל ניקוי: `ollama pull gemma3:4b` (וגם `qwen2.5:1.5b` כגיבוי קל)
- [ ] בדיקת חומרה: מדידת RAM פנוי, האם יש GPU (CUDA) או CPU בלבד
- [ ] בנצ'מרק ראשוני: תמלול קובץ עברי של 5 דקות, מדידת זמן ו־RAM

### תוצר
סקריפט `benchmark.py` שמדפיס: זמן תמלול, יחס real-time factor, צריכת זיכרון, טוקנים/שנייה של ה־LLM.

### קריטריון מעבר
תמלול מהיר מ־1x זמן אמת, LLM מעל 15 טוקנים/שנייה. אם לא — מעבר למודלים קלים יותר (turbo→base, 4B→1.5B) לפני המשך.

## שלב 1: MVP — תמלול קבצים (שבוע 1)

### משימות
- [ ] מודול `transcriber.py`: קלט קובץ אודיו/וידאו → המרה עם ffmpeg → faster-whisper עם `language="he"`, `beam_size=5`
- [ ] פלט: טקסט מלא + סגמנטים עם חותמות זמן (לצורך SRT עתידי)
- [ ] טיפול בקבצים ארוכים: עיבוד בצ'אנקים, מד התקדמות
- [ ] CLI בסיסי: `python transcribe.py path/to/file.mp3 -o output.txt`
- [ ] בדיקות על 5 סוגי אודיו: הקלטת ווטסאפ, פגישת זום, פודקאסט, הרצאה, דיבור עם רעש רקע

### תוצר
כלי CLI שמתמלל כל קובץ אודיו/וידאו לעברית.

### קריטריון מעבר
WER (שיעור שגיאות מילים) סביר על ההקלטות שלך — בדיקה ידנית של 3 קטעים, פחות מ־10 שגיאות מהותיות לדקה.

### סיכונים
- אודיו רועש מוריד דיוק → להוסיף נרמול עוצמה (loudnorm של ffmpeg) לפני תמלול.

## שלב 2: שכבת ה־LLM — ניקוי ועיבוד (שבוע 2)

### משימות
- [ ] מודול `cleaner.py`: חיבור ל־Ollama דרך REST API מקומי (localhost:11434)
- [ ] כתיבת system prompt לניקוי בעברית. עקרונות:
  - הסר מילות מילוי: אה, אמ, כאילו, יענו, אוקיי (בתחילת משפט)
  - אחד תיקוני אמצע־משפט ("ניפגש ביום שני... לא, שלישי" → "ניפגש ביום שלישי")
  - הוסף פיסוק וחלק למשפטים
  - אל תוסיף מידע, אל תשנה משמעות, שמור על משלב הדובר
  - החזר אך ורק את הטקסט הנקי, ללא הקדמות
- [ ] עיבוד בצ'אנקים של ~500 מילים עם חפיפה של משפט (להקשר)
- [ ] מצב השוואה: שמירת גולמי + נקי זה לצד זה לבדיקת איכות
- [ ] 4 טרנספורמציות כפרומפטים נפרדים: נקודות עיקריות / פורמלי / קצר / ארוך
- [ ] בדיקת A/B: Gemma 3 4B מול Qwen 2.5 1.5B על אותם קלטים — איכות מול מהירות

### תוצר
`transcribe.py --clean` שמפיק שני קבצים: גולמי ונקי, ופקודת `--transform keypoints`.

### קריטריון מעבר
על 10 קטעי דיבור ספונטני: הטקסט הנקי קריא, ללא אובדן משמעות, ללא "המצאות" של המודל.

### סיכונים
- המודל "מתחכם" ומוסיף תוכן → להדק את הפרומפט, להוריד temperature ל־0.1–0.3.
- עברית חלשה במודל קטן → לנסות DictaLM או לעלות ל־Gemma 4B.
