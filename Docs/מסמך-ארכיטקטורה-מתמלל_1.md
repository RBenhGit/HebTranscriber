# מתמלל מקומי בסגנון Eloquent — מסמך ארכיטקטורה

תאריך: יוני 2026

## רקע: איך Google AI Edge Eloquent בנוי

Eloquent של גוגל הוא לא "מתמלל" קלאסי אלא צינור דו־שלבי: זיהוי דיבור + מודל שפה שמנקה ומעבד.

- המודלים רצים מקומית על המכשיר ללא שרת (offline-first).
- תמלול חי מוצג תוך כדי דיבור; כשהמשתמש עוצר, המערכת מסירה מילות מילוי ("אה", "אמ") ומתקנת ניסוח לפי כוונה — לא מילה במילה.
- טרנספורמציות טקסט מקומיות: נקודות עיקריות, פורמלי, קצר, ארוך.
- מצב ענן אופציונלי (Gemini) לליטוש מתקדם.
- אוצר מילים אישי, היסטוריית סשנים עם חיפוש, העתקה אוטומטית ללוח.

טכנית: Gemma 3n מקבל אודיו ישירות — מקודד אודיו מבוסס USM הופך כל 160ms של קול לטוקן (כ־6 טוקנים לשנייה), והטוקנים מוזנים למודל השפה.

## החלטת ארכיטקטורה מרכזית: שני מודלים, לא אחד

גוגל מאחדים את שני השלבים במודל מולטימודלי אחד. לפרויקט עצמאי, ובמיוחד בעברית, עדיפה הפרדה:

- **Whisper (מומחה דיבור):** נאמנות מילולית, ביצועים חזקים באודיו ארוך, מצבי כשל צפויים.
- **LLM מולטימודלי (Gemma 3n):** מוגבל בחלון הקשר ובזיכרון KV cache במכשיר; באודיו ארוך עלול לדלג על התמלול ולענות "תשובה חכמה" במקום תמלול.

המסקנה: ASR ייעודי לתמלול + LLM טקסטואלי לניקוי ועיבוד.

## הצינור (Pipeline)

```
מיקרופון / קובץ אודיו (16kHz)
        │
        ▼
Silero VAD — זיהוי הפסקות דיבור (הטריגר לניקוי)
        │
        ▼
שלב 1: ASR — faster-whisper + ivrit-ai/whisper-large-v3-turbo-ct2
        │   (טקסט גולמי: מילות מילוי, תיקוני אמצע־משפט)
        ▼
שלב 2: LLM מקומי — Ollama עם Gemma 3 4B / Qwen 1.5–4B
        │   (ניקוי, פיסוק, ניסוח לפי כוונה)
        ▼
פלט: טקסט נקי → לוח (clipboard) │ טרנספורמציות │ היסטוריה מקומית
```

## דרישות משלב ה־ASR (שלב 1) — קריטי לעברית

ה־ASR של Gemma חזק באנגלית ובשפות לטיניות; עברית אינה ברשימת החוזקות. הפתרון המקומי הטוב ביותר לעברית:

- **מודל:** `ivrit-ai/whisper-large-v3-turbo-ct2` (ל־faster-whisper) או גרסת ggml (ל־whisper.cpp). מבוסס whisper-large-v3, state-of-the-art לעברית.
- **אזהרה:** זיהוי השפה במודל הוחלש באימון — חובה לקבוע `language="he"` במפורש. גם יכולת התרגום הוחלשה.
- **חומרה:** ~1.5–2GB RAM לגרסת turbo מקוונטזת; זמן אמת גם על CPU סביר.
- **VAD:** Silero VAD (מודל זעיר, ~2MB) לזיהוי מתי המשתמש עוצר — הטריגר ששולח מקטע ל־LLM.

## דרישות ממודל השפה המקומי (שלב 2)

| דרישה | ערך |
|---|---|
| גודל | 2–4 מיליארד פרמטרים, קוונטיזציה 4-bit |
| זיכרון | ~2–4GB RAM למודל |
| מהירות | 15–30+ טוקנים/שנייה (כדי שהניקוי ירגיש מיידי) |
| חלון הקשר | 4–8K טוקנים (מעבדים מקטע אחד בכל פעם) |
| מועמדים | Gemma 3 4B, Qwen 2.5/3 בגדלים 1.5–4B, DictaLM (עברית) |
| Runtime | דסקטופ: llama.cpp / Ollama. מק/מובייל: MLX / LiteRT |

המודל לא צריך להיות "חכם" — הוא מבצע 4 משימות מוגדרות בפרומפט הדוק:
1. הסרת מילות מילוי ותיקוני אמצע־משפט
2. פיסוק וחלוקה למשפטים
3. ניסוח מחדש לפי כוונה (לא מילולי)
4. טרנספורמציות: נקודות עיקריות / פורמלי / קצר / ארוך

## תקציב משאבים כולל

- ASR (turbo, מקוונטז): ~1.5–2GB
- LLM (4B, 4-bit): ~2–4GB
- VAD + תקורה: ~0.5GB
- **סה"כ: ~4–6GB RAM, רץ לגמרי אופליין.**
